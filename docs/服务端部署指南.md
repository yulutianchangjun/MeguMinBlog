# 服务端部署指南（Spring Boot + MySQL + Redis + Nginx）

> 适用版本：第五版（前后端分离）
> 域名示例：`your-domain.com`
> 相关文件：`backend/`、`deploy/`、`docker-compose.yml`、`.env.example`

---

## 1. 架构总览

```
Internet (HTTPS 443)
        │
        ▼
   Nginx (your-domain.com)
   ├── /            → Vue 3 SPA（dist/）
   ├── /uploads/    → 上传的封面 / 音频（宿主机 data/uploads）
   └── /api/        → Spring Boot :8080
                         ├── MySQL 8.0（文章、综集、留言、音乐、签到、纪念日、站点配置）
                         └── Redis 7.x（JWT 会话、限流、PV/UV）
```

- 前端：Vue 3 + TypeScript + Pinia + Vue Router + Axios，**全部数据来自 REST API**（无静态降级数据；后端不可用时前台显示空态与错误提示）。
- 后端：JDK 17 + Spring Boot 3.3 + MyBatis-Plus 3.5 + MySQL 8 + Redis 7。
- 鉴权：账号密码 → BCrypt 校验 → JWT（HS256）→ Redis 白名单；退出登录即删除会话。
- 防刷：Redis 分钟/小时双窗口限流 + Cloudflare Turnstile 服务端校验 + Jsoup 文本净化。
- 部署：Docker Compose 一键拉起四个容器。

## 3. 本地开发

### 3.1 准备 MySQL 与 Redis

```bash
# MySQL 8.0：建库
mysql -uroot -p -e "CREATE DATABASE blog_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

Redis 7 任一方式启动即可（本机、Docker、Memurai 均可），默认 `localhost:6379`，无密码。

### 3.2 启动后端

```bash
cd backend
MYSQL_PASSWORD=你的密码 mvn spring-boot:run
# 或打包后运行
mvn -DskipTests package
MYSQL_PASSWORD=你的密码 java -jar target/app.jar
```

`dev` profile 启动时只自动执行 `schema.sql`（`CREATE TABLE IF NOT EXISTS`，幂等建表），**不会插入任何数据**——初始文章与博主账号都需要手工导入：

```bash
# 可选：导入初始内容（重复执行安全，INSERT IGNORE）
mysql -uroot -p --default-character-set=utf8mb4 blog_db < backend/src/main/resources/seed.sql

# 创建博主账号（必做，见下节「创建博主账号」）
```

> 手动 `mysql < seed.sql` 请加 `--default-character-set=utf8mb4`，否则中文会乱码。

#### 创建博主账号（sys_user）

后端启动不会创建账号，也不接受任何明文密码。流程：

```bash
# 1. 首次使用先装依赖
cd scripts && npm install

# 2. 生成 BCrypt 哈希（交互输入，避免明文进 shell 历史）
node hash-password.mjs

# 3. 写入数据库（换成你自己的用户名/昵称与刚才的哈希）
mysql -uroot -p blog_db -e "INSERT INTO sys_user (username, password, nickname, status) VALUES ('你的用户名', '<上一步的哈希>', '昵称', 1);"
```

忘记密码时同理：`UPDATE sys_user SET password='<新哈希>' WHERE username='你的用户名';`

### 3.3 启动前端

```bash
npm install
npm run dev     # http://localhost:5173，读取 .env.development
```

`.env.development` 默认：

```ini
VITE_API_BASE_URL=http://localhost:8080/api
VITE_APP_ENV=development
VITE_TURNSTILE_SITE_KEY=
```

后端未启动时，前台各页面显示空态与「无法连接后端」提示（登录/留言/签到/曲库同样不可用）；数据没有任何本地兜底。

### 3.4 内容迁移

修改 `content/posts/*.md` 后重新生成种子：

```bash
node scripts/gen-seed.mjs
# 更新 backend/src/main/resources/seed.sql（手工导入用，启动与容器首启都不会自动执行）
# 种子包含：文章/分类/综集、站点配置（开站日期）、纪念日、内置合成曲
```

种子使用 `INSERT IGNORE`，不会覆盖数据库中已存在的同 slug 文章与同主键站点数据。

## 4. 生产环境变量

复制 `.env.example` 为 `.env`（已被 `.gitignore` 忽略），逐项修改：

| 变量 | 说明 |
| --- | --- |
| `MYSQL_DATABASE` | 数据库名，默认 `blog_db` |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码，建议 24 位随机 |
| `REDIS_PASSWORD` | Redis 密码，必填 |
| `JWT_SECRET` | JWT 签名密钥，**至少 32 个字符** |
| `TURNSTILE_ENABLED` | 是否启用人机校验（默认 true） |
| `TURNSTILE_SECRET` | Cloudflare Turnstile 服务端 Secret，留空则跳过校验 |

> 博主账号**没有**对应的环境变量：用 `scripts/hash-password.mjs` 生成哈希后手工插入 `sys_user`（见 3.2 节），数据库里只存 BCrypt 哈希，不存在任何明文密码。

前端构建变量在 `.env.production`：

```ini
VITE_API_BASE_URL=/api
VITE_APP_ENV=production
VITE_TURNSTILE_SITE_KEY=你的 Turnstile Site Key
```

> `VITE_*` 会被编译进前端包，**只能放公开值**（API 路径、Turnstile Site Key）。任何 Secret、数据库密码都不要写进前端。

## 5. Docker Compose 部署

### 5.1 首次上线

```bash
# 1. 服务器安装 Docker / Compose
sudo apt update && sudo apt install -y docker.io docker-compose-plugin git
sudo systemctl enable --now docker

# 2. 拉代码
git clone <你的仓库> /opt/blog && cd /opt/blog

# 3. 配置环境变量
cp .env.example .env
vim .env    # 填 MySQL/Redis 密码、JWT_SECRET

# 4. 构建前端（在本地或服务器上都可以）
npm ci
npm run build          # 产物 dist/ 会被 nginx 容器挂载

# 5. 申请证书（先把域名 A 记录指向服务器）
sudo certbot certonly --standalone -d your-domain.com -d www.your-domain.com
sudo cp /etc/letsencrypt/live/your-domain.com/fullchain.pem deploy/nginx/ssl/your-domain.com.crt
sudo cp /etc/letsencrypt/live/your-domain.com/privkey.pem  deploy/nginx/ssl/your-domain.com.key

# 6. 一键启动
docker compose up -d --build
docker compose ps
```

首次启动顺序：MySQL 初始化（只执行 `01-schema.sql` 建表，**不灌任何数据**）→ Redis → 后端 → Nginx。

启动后还需两步（容器里执行或宿主机直连均可）：

```bash
# 7a. 可选：导入初始内容（不导也行，直接后台发文）
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" blog_db \
  < backend/src/main/resources/seed.sql

# 7b. 必做：手工创建博主账号（见 3.2 节「创建博主账号」）
node scripts/hash-password.mjs
docker compose exec mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" blog_db \
  -e "INSERT INTO sys_user (username, password, nickname, status) VALUES ('你的用户名', '<哈希>', '昵称', 1);"
```

访问 `https://your-domain.com`，用刚插入的账号密码登录后台（连点头像 5 次或 `Ctrl + Shift + L`）。

### 5.2 日常更新

```bash
git pull
npm ci && npm run build
docker compose up -d --build backend nginx
```

只改了前端：重建前端 + `docker compose restart nginx` 即可（Nginx 直接挂载 `dist/`）。
只改了后端：`docker compose up -d --build backend`。
改了 `content/`：先 `node scripts/gen-seed.mjs`，再重建后端；或在后台直接发文。

### 5.3 数据与备份

```bash
# MySQL 逻辑备份
docker compose exec -T mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction blog_db \
  | gzip > backup/blog-$(date +%F).sql.gz

# 上传文件
tar czf backup/uploads-$(date +%F).tar.gz data/uploads

# 恢复
gunzip -c backup/blog-2026-11-05.sql.gz | docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" blog_db
```

建议加一条 crontab 每日备份，并把 `backup/` 同步到对象存储。

## 6. 博主身份与密码

- 博主账号由本人手工插入 `sys_user`（见 3.2 节），库中只存 BCrypt 哈希；代码与配置里**没有任何默认账号、明文密码或环境变量后门**。
- 忘记密码：`node scripts/hash-password.mjs` 生成新哈希后 `UPDATE sys_user SET password='<新哈希>' WHERE username='...';`
- 登录后改密码（旧密码仍需正确）：
  ```bash
  curl -X POST https://your-domain.com/api/auth/password \
    -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
    -d '{"oldPassword":"旧密码","newPassword":"新密码至少8位"}'
  ```
  或在数据库里把 `sys_user.password` 换成新的 BCrypt 哈希后重启（不推荐手写哈希）。
- 忘记密码：`node scripts/hash-password.mjs` 生成新哈希后
  ```sql
  UPDATE sys_user SET password = '<新 BCrypt 哈希>' WHERE username = '你的用户名';
  ```

> 登录态：JWT 有效期 7 天，同时 Redis 中有白名单；退出登录会立刻删除，盗用的旧 token 随即失效。

## 7. Cloudflare Turnstile

1. Cloudflare Dashboard → Turnstile → Add site，Hostname 填 `your-domain.com` 与 `www.your-domain.com`（本地调试再加 `localhost`）。
2. 把 **Site Key** 填到 `.env.production` 的 `VITE_TURNSTILE_SITE_KEY`，重新 `npm run build`。
3. 把 **Secret Key** 填到 `.env` 的 `TURNSTILE_SECRET`，`docker compose up -d backend`。

后端在留言入库前调用 `https://challenges.cloudflare.com/turnstile/v0/siteverify` 校验；失败返回 400，服务不可用返回 503。

> 不配置 Secret 时后端会跳过校验（方便本地开发）。生产务必配置，否则只剩 IP 限流这一层。

## 9. 常见问题

| 现象 | 排查 |
| --- | --- |
| 502 Bad Gateway | `docker compose logs backend`；后端未起或 8080 未监听 |
| 前端请求 404 | `VITE_API_BASE_URL` 是否为 `/api`，Nginx 是否代理 `/api/` |
| CORS 报错 | `CORS_ORIGINS` 是否包含前端域名；本项目已放行 OPTIONS 预检 |
| 登录 401 | 账号密码错误；或 Redis 未启动导致会话写不进去 |
| 保存 401 | token 过期（7 天）或 Redis 被清空，重新登录 |
| 留言 429 | 触发限流：同 IP 每分钟 1 条、每小时 5 条（Redis 键 `rl:msg:*`） |
| 留言 400 人机校验 | Turnstile Site Key / Secret 不匹配，或域名未加白名单 |
| 上传成功但图片 404 | `data/uploads` 未挂载到 Nginx 的 `/usr/share/nginx/uploads` |
| 中文乱码 | 数据库/表/连接串字符集；手动导入时加 `--default-character-set=utf8mb4` |
| 登录 401：提示账号不存在 | 正常：博主账号需手工插入 `sys_user`（见 3.2 节），启动不会自动创建 |
| 首次启动没有文章 | 正常：启动不灌数据；需手工导入 `seed.sql` 或直接后台发文 |
| 后台看不到草稿 | 正常：公开接口不返回隐藏/草稿，登录后走 `/api/admin/posts` |

## 10. 安全清单

- `JWT_SECRET` 使用 32 位以上随机值，定期轮换（会让所有会话失效）。
- 博主密码为强密码，仅以 BCrypt 哈希存于 `sys_user`；代码与配置中无默认账号/明文密码。
- MySQL / Redis 不对公网暴露端口（compose 未映射 3306/6379）。
- 生产启用 Turnstile；只在前端放 Site Key。
- 上传接口限制类型与大小（图片 8MB / 音频 30MB），文件名为随机 UUID。
- 留言内容用 Jsoup `Safelist.none()` 净化，颜色只接受 `#RRGGBB`，墙体/纸纹走白名单。
- 定期 `mysqldump` + 上传目录备份；证书到期前 `certbot renew`。
- 若使用 CDN（Cloudflare），确保 Nginx 的 `X-Forwarded-For` 不被伪造覆盖，或在 Cloudflare 侧开启 Authenticated Origin Pulls。

## 11. 单机生产部署参考（宿主机 nginx + 三容器）

小内存服务器（如 2G 及以下）推荐「宿主机 nginx + 三容器」形态，与上面的纯 Compose 方案相比，前端静态资源与 TLS 交给宿主机 nginx，容器只跑数据与业务，资源占用更省。

### 11.1 目录结构

```
/var/www/blog/
├── dist/                 # 前端构建产物（npm run build 后上传）
├── backend/
│   ├── app.jar           # 本地 mvn package 产物
│   └── Dockerfile        # 仅 JRE 运行层（服务器不做 maven 构建）
├── mysql-init/
│   └── 01-schema.sql     # 容器首启只建表，不灌数据
├── seed.sql              # 手工导入的初始内容
├── data/{mysql,redis,uploads}/
├── docker-compose.yml    # 见仓库 deploy/docker-compose.server.yml
└── .env                  # 600 权限，随机生成的 MYSQL/REDIS/JWT 密钥

宿主机 nginx（/etc/nginx/sites-enabled/blog.conf，见 deploy/nginx/blog.server.conf）
├── your-domain.com / www     → /var/www/blog/dist（SPA）+ /api/ → 127.0.0.1:8080 + /uploads/ → data/uploads
├── admin.your-domain.com     → 301 到主站（后台已集成在主站）
└── HTTP → HTTPS 301，证书沿用 /etc/nginx/ssl/your-domain.com.pem|.key
```

- 容器：`blog-mysql`（450m）、`blog-redis`（100m，maxmemory 64m）、`blog-backend`（450m，`-Xmx280m`），均 `restart: always`。
- 上传目录 `data/uploads` 由 nginx 直接分发，不经过后端。

### 11.2 更新前端

```bash
npm run build
scp -r dist/* root@your-server-ip:/var/www/blog/dist/
```

### 11.3 更新后端

```bash
cd backend && mvn -DskipTests package
scp target/app.jar root@your-server-ip:/var/www/blog/backend/app.jar
ssh root@your-server-ip "cd /var/www/blog && docker compose up -d --build backend"
```

### 11.4 备份

```bash
ssh root@your-server-ip 'set -a; . /var/www/blog/.env; set +a; \
  docker exec blog-mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction blog_db | gzip > /root/blog-$(date +%F).sql.gz; \
  tar czf /root/uploads-$(date +%F).tar.gz -C /var/www/blog/data uploads'
```

### 11.5 常见运维

| 操作 | 命令 |
| --- | --- |
| 看容器状态 | `cd /var/www/blog && docker compose ps` |
| 看后端日志 | `docker logs -f blog-backend` |
| 重启后端 | `cd /var/www/blog && docker compose restart backend` |
| 改博主密码 | 本地 `node scripts/hash-password.mjs` → `docker exec blog-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" blog_db -e "UPDATE sys_user SET password='<哈希>'"` |
| 重载 nginx | `nginx -t && systemctl reload nginx` |

### 11.6 性能调优（内存 ≤ 2G 的小机器）

已落地的措施：

- **2G swap**（`/swapfile`，fstab 持久化，`vm.swappiness=10`）：防止内存压力下的 OOM / 卡死。
- **MySQL**：`--performance-schema=off --innodb-buffer-pool-size=128M --skip-name-resolve`，常驻内存 395M → 约 150M。
- **JVM**：容器内 `-Xmx280m`（mem_limit 450m）。
- **Redis**：`--maxmemory 64m` + allkeys-lru。
- **nginx**：gzip（comp_level 6，主 JS 963KB → 322KB）；`/assets/` 带哈希文件名 `Cache-Control: public, immutable` 30 天，`index.html` no-cache 保证发版即生效。

进一步提速的选项（跨境服务器 + 国内访客场景）：

1. 域名接入 Cloudflare（免费）：CDN 缓存静态资源 + TLS 提前终止，国内访问首屏可明显改善；Turnstile 与之同家，配置顺手。
2. 国内 CDN / 国内服务器：根治跨境延迟，但 80/443 需域名备案。
3. 前端主包 963KB 可做 vendor 拆分（naive-ui 按需），属于锦上添花。
