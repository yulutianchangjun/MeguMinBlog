## 1. 先理解：部署到底在做什么

你在本地开发时是这样的：

```
浏览器 → Vite 开发服务器(5173) → Spring Boot(8080) → 本地 MySQL/Redis
```

部署就是把这一整套搬到一台 24 小时开机的服务器上，让别人也能访问。但这套东西不能原样搬：

| 本地开发 | 线上 | 原因 |
| --- | --- | --- |
| `npm run dev` 的 Vite | 编译成静态文件（`dist/`），交给 Nginx | Vite 开发服务器性能差、不支持长时间运行 |
| Spring Boot 直接跑 | 打成 jar，装进 Docker 容器 | 容器隔离环境，换机器不用重装依赖 |
| 本地 MySQL/Redis | 容器里的 MySQL/Redis，数据挂载到宿主机目录 | 容器删了数据不丢 |
| 端口 5173/8080 直接裸露 | 只有 Nginx 的 80/443 对外，其他全在内网 | 安全 |

最终形态（本项目的方案）：

```
                 互联网
                    │  80 / 443
                    ▼
        ┌───────────────────────┐
        │  宿主机 Nginx          │  ← 只它对外
        │  ├ /          → dist/  │     前端静态文件直接从磁盘读
        │  ├ /api/      → :8080  │     转发给后端容器
        │  └ /uploads/  → 磁盘    │     上传的图片音频
        └───────────┬───────────┘
                    │ 127.0.0.1:8080
        ┌───────────▼───────────┐
        │  blog-backend 容器     │  Java 进程，跑 jar
        └───────────┬───────────┘
                    │ 容器内网
        ┌───────────┴───────────┐
        ▼                       ▼
   blog-mysql              blog-redis
   数据在 data/mysql        数据在 data/redis
```

**关键理解**：容器之间通过 Docker 内网用**服务名**互相访问（`mysql:3306`、`redis:6379`），不需要知道 IP。宿主机通过 `127.0.0.1:8080` 访问后端，因为 compose 里写了 `ports: - "127.0.0.1:8080:8080"`。

## 2. 准备阶段：服务器、域名、SSH

### 2.1 你需要准备

| 东西 | 说明 |
| --- | --- |
| 一台 Linux 服务器 | Ubuntu 22.04 最省心；1 核 2G 内存起步（1.6G 也能跑，见第 4 章调优） |
| 一个域名 | 阿里云/腾讯云买，几十块一年；本文用 `your-domain.com` 代替 |
| 域名解析 | 在域名服务商控制台加 A 记录，指向服务器公网 IP |
| SSH 客户端 | Windows 自带 `ssh`（Win10+），或 Xshell / Termius |

### 2.2 第一次连接服务器

```bash
ssh root@your-server-ip
```

逐段解释：

- `ssh` —— 远程登录命令
- `root` —— 要登录的用户名，`root` 是超级管理员
- `@` —— 分隔符
- `your-server-ip` —— 服务器公网 IP，例如 `1.2.3.4`

第一次连接会提示：

```
The authenticity of host '1.2.3.4' can't be established.
ED25519 key fingerprint is SHA256:xxxx.
Are you sure you want to continue connecting (yes/no)?
```

输入 `yes` 回车——这是让你确认"这台服务器是不是你要连的"，指纹只出现一次，之后会记到 `~/.ssh/known_hosts`。

然后输入密码（输入时屏幕不显示任何字符，这是正常的），回车。

看到这样的提示就成功了：

```
root@iZxxxxxZ:~#
```

`~` 表示你现在在 root 用户的家目录（`/root`），`#` 表示你是超级管理员（普通用户是 `$`）。

### 2.3 配置免密登录（强烈建议）

每次部署都要输密码太痛苦，而且密码登录不安全。用密钥替代：

**在你的本地电脑**（不是服务器）执行：

```bash
ssh-keygen -t ed25519 -C "my-blog"
```

- `-t ed25519`：密钥类型，比老式 RSA 更短更安全
- `-C "my-blog"`：备注，方便以后识别

一路回车（密码短语可以留空）。会生成两个文件：

```
~/.ssh/id_ed25519       ← 私钥，绝对不要给任何人
~/.ssh/id_ed25519.pub   ← 公钥，要放到服务器上
```

把公钥复制到服务器：

```bash
ssh-copy-id root@your-server-ip
```

Windows 没有 `ssh-copy-id` 时，手动来：

```bash
cat ~/.ssh/id_ed25519.pub | ssh root@your-server-ip "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

之后 `ssh root@your-server-ip` 就不用密码了。

**关掉密码登录**（服务器上执行）：

```bash
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh
```

⚠️ 改之前**务必确认新开一个终端能用密钥登录成功**，否则会把自己锁在外面（云厂商控制台通常有 VNC 可以救）。

改完后，所有 `ssh` / `scp` 命令都可以加参数强制检查失败即报错：

```bash
ssh -o BatchMode=yes root@your-server-ip "echo ok"
```

`BatchMode=yes` 禁止交互式提问，脚本里用它能避免卡在密码提示上。

## 3. Linux 基础：目录结构与必备命令

### 3.1 目录结构：东西为什么放这些地方

Linux 根目录 `/` 下面是约定俗成的分工，理解了这个，你就知道部署文件该往哪放：

```
/
├── bin/      系统基本命令（ls、cp 等），不要动
├── boot/     内核与启动文件，不要动
├── dev/      设备文件
├── etc/      所有程序的配置文件
│   ├── nginx/            ← Nginx 配置在这里
│   │   ├── nginx.conf    主配置
│   │   ├── sites-enabled/ 启用的站点（我们的 blog.conf 放这）
│   │   └── ssl/          我们放证书的地方
│   └── ssh/sshd_config   SSH 配置
├── home/     普通用户的家目录
├── opt/      第三方大型软件（可选）
├── root/     root 用户的家目录（~ 就是它）
├── tmp/      临时文件，重启可能被清空
├── usr/      系统程序与库
└── var/      经常变化的数据
    ├── log/      日志（nginx 日志在 /var/log/nginx/）
    ├── lib/      数据库、容器数据
    └── www/      ← 网站文件通常放这里
```

**我们把项目放在 `/var/www/blog`**，理由是：

- `/var` 本来就是放"会变化的数据"的位置，网站内容、上传文件、数据库文件都属于这类
- `/etc` 只放配置，`/home` 不适合服务程序，`/opt` 是给独立软件包准备的
- 备份时只要打包 `/var/www/blog` 就能覆盖全部业务数据

最终目录结构：

```
/var/www/blog/
├── dist/                前端静态文件（Nginx 直接读）
│   ├── index.html
│   └── assets/          带 hash 的 js/css/图片
├── backend/
│   ├── app.jar          Spring Boot 可执行 jar
│   └── Dockerfile       只做 COPY app.jar 的极简镜像
├── mysql-init/
│   └── 01-schema.sql    建表脚本（容器首次启动自动执行）
├── data/
│   ├── mysql/           MySQL 数据文件（千万别手动改）
│   ├── redis/           Redis 持久化文件
│   └── uploads/         用户上传的图片/音频
├── docker-compose.yml
└── .env                 密码等敏感配置（权限 600）
```

### 3.2 必备命令（按部署会遇到的顺序）

**看位置与列文件**

```bash
pwd                    # 我现在在哪个目录 → /root
ls                     # 列当前目录
ls -l                  # 详细列表（权限、大小、时间）
ls -lh                 # 同上，大小显示成 KB/MB 更好读
ls -a                  # 显示隐藏文件（.env 这种点开头的是隐藏文件）
cd /var/www/blog       # 进入目录
cd ..                  # 上一级
cd ~                   # 回家目录
```

**创建、复制、移动、删除**

```bash
mkdir -p /var/www/blog/data/uploads
# -p：父目录不存在就一起创建，已存在也不报错（部署脚本里必用）

cp app.jar /var/www/blog/backend/          # 复制文件
cp -a dist dist.bak-1115                    # -a 保留权限与时间，适合备份目录
mv /tmp/app.jar /var/www/blog/backend/      # 移动（也用来重命名）

rm -rf dist.new
# -r 递归删目录，-f 不询问。⚠️ 这是 Linux 上最危险的命令之一，
# 执行前一定 pwd 看清楚自己在哪，且路径要写全
```

**看文件内容**

```bash
cat .env                 # 整个文件打出来（适合短文件）
less docker-compose.yml  # 分页查看，q 退出（适合长文件）
tail -f /var/log/nginx/error.log   # 实时跟踪，Ctrl+C 退出（排错最常用）
grep -n "proxy_pass" /etc/nginx/sites-enabled/blog.conf   # 带行号搜索
```

**压缩与解压**

```bash
tar -czf dist.tgz -C dist .
# tar：打包工具
# -c 创建归档   -z 用 gzip 压缩   -f 指定文件名
# -C dist .  表示先切到 dist 目录，再把里面的内容打包（注意是 `.`）

tar -xzf dist.tgz -C dist.new
# -x 解开   -z gzip   -f 文件名   -C 解压到指定目录
```

为什么不用 `scp -r dist` 直接传整个目录？因为目录里几十个小文件，每个都要单独握手，跨境网络下比打成一个包慢好几倍。

**权限**

```bash
chmod 600 .env        # 只有属主能读写（密码文件必须这么设）
chmod 755 start.sh    # 属主可读写执行，其他人只读
chown -R blog:blog /app/uploads   # 改属主（-R 递归）
```

数字含义：`rwx` 三个权限分别对应 4/2/1，`600` = `rw-------`。

**系统状态**

```bash
df -h          # 磁盘用了多少（部署前看一眼，满了会启动失败）
free -m        # 内存（MB）
uptime         # 负载，load average 三个数字分别代表 1/5/15 分钟平均
ss -lntp       # 当前监听的端口和对应进程（排"端口被占用"必用）
ps aux         # 所有进程
```

**服务管理**

```bash
systemctl status nginx     # 看 nginx 状态
systemctl reload nginx     # 重载配置（不中断连接）
systemctl restart nginx    # 重启
systemctl enable nginx     # 开机自启
journalctl -u nginx -n 50  # 看 nginx 最近的系统日志
```

**Docker**

```bash
docker ps                                  # 运行中的容器
docker ps -a                               # 包括已停止的
docker logs -f blog-backend                # 实时看后端日志
docker exec -it blog-mysql bash            # 进容器内部
docker stats --no-stream                   # 各容器 CPU/内存占用
docker compose ps                          # compose 管理的服务状态
docker compose up -d --build backend       # 重新构建并启动某个服务
docker compose down                        # 停止并删除容器（数据卷还在）
```

`-d` 是后台运行，`--build` 是重新构建镜像（改了 Dockerfile 或 jar 后必须加）。

## 4. 安装运行环境

### 4.1 更新系统

```bash
apt update          # 刷新软件源列表（不升级任何东西）
apt upgrade -y      # 升级已安装的软件包
```

`apt` 是 Ubuntu/Debian 的包管理器，相当于手机的应用商店。

### 4.2 安装 Docker

官方一键脚本（最省事）：

```bash
curl -fsSL https://get.docker.com | sh
```

装完验证：

```bash
docker version
docker compose version
```

注意是 `docker compose`（中间空格，v2 插件），不是老的 `docker-compose`（中间横线）。

设置开机自启：

```bash
systemctl enable docker
```

### 4.3 安装 Nginx

```bash
apt install -y nginx
systemctl enable nginx
systemctl start nginx
```

浏览器访问 `http://your-server-ip`，看到 "Welcome to nginx!" 就说明装好了。

> **不需要在服务器装 JDK 和 Maven**。后端 jar 在你自己电脑上构建好再上传，服务器只负责运行。这样服务器上不用装几百 MB 的构建工具。

### 4.4 （可选）小内存机器调优

1.6G 内存的机器建议加 swap，防止内存紧张时进程被系统杀掉：

```bash
fallocate -l 2G /swapfile      # 创建 2G 文件
chmod 600 /swapfile            # 只有 root 能读写
mkswap /swapfile               # 格式化成 swap
swapon /swapfile               # 启用
echo '/swapfile none swap sw 0 0' >> /etc/fstab   # 写入 fstab，重启后自动启用
sysctl -w vm.swappiness=10     # 尽量不用 swap，只在真的不够时用
```

验证：`free -m` 的 Swap 行不再是 0。

## 5. 本地打包：前端与后端

以下都在**你自己的电脑**上执行，在项目根目录。

### 5.1 前端打包

```bash
npm ci            # 按 package-lock.json 装依赖（比 npm install 更严格可复现）
npm run build     # Vite 构建，输出到 dist/
```

构建完会看到类似输出：

```
dist/index.html                   0.71 kB
dist/assets/index-CPkLaPZN.js   965.54 kB │ gzip: 325.60 kB
dist/assets/BoardView-B3r_YnHY.js  17.25 kB │ gzip: 6.41 kB
✓ built in 8.69s
```

**文件名里那串 `CPkLaPZN` 是什么？** 是文件内容的哈希值。内容一变，哈希就变，文件名跟着变。这样浏览器可以放心地长期缓存（`/assets/` 设了 30 天 immutable 缓存），而 `index.html` 每次都不缓存——发新版时 index.html 会引用新的哈希文件名，浏览器自然就拉到新文件了。这是现代前端部署的标准做法。

`dist/` 里就是最终要给 Nginx 的静态文件，**不要**把 `src/`、`node_modules/` 传上去。

### 5.2 后端打包

```bash
cd backend
mvn -DskipTests package
```

- `-DskipTests` 跳过单元测试，加快打包（部署前你应该在本地跑过测试）
- `package` 编译 + 打 jar

产物在 **`backend/blog-admin/target/app.jar`**（约 40MB）。

为什么这么大？因为这是 **fat jar**：Spring Boot 把所有依赖（tomcat、mybatis、jedis……）都塞进这一个文件里，服务器上只要有 JDK 17 就能 `java -jar` 直接跑，不需要装依赖。

本项目是 RuoYi 风格多模块：

```
blog-common     通用响应、异常、工具、DTO
blog-framework  Web 配置、JWT、限流、Turnstile
blog-system     实体、Mapper、业务服务
blog-admin      Controller、启动类、resources —— jar 在这里产出
```

改哪一层就进对应目录，构建命令始终是在 `backend/` 根目录执行上面那条。

## 6. 上传文件到服务器

### 6.1 直接传（适合单个文件）

```bash
scp -C backend/blog-admin/target/app.jar root@your-server-ip:/tmp/app.jar
```

- `scp` 安全复制，走的就是 SSH 通道
- `-C` 传输时压缩（jar 本身已压缩，但网络差时仍有帮助）
- 冒号左边是本地路径，右边是 `用户@主机:远程路径`
- 先传到 `/tmp` 是个好习惯：给自己留一步"校验完再替换"的机会

### 6.2 打包传（适合目录，速度快很多）

```bash
tar -czf /tmp/dist.tgz -C dist .
scp -C /tmp/dist.tgz root@your-server-ip:/tmp/dist.tgz
```

本地 40MB 的 dist，压缩后通常只有几 MB，跨境上传时间大幅缩短。

### 6.3 校验与替换

上传完先比对大小：

```bash
ls -l /tmp/app.jar      # 和本地 ls -l 对比字节数
```

一致后再替换，并且**先备份旧的**：

```bash
ssh root@your-server-ip '
  cd /var/www/blog &&
  cp -a backend/app.jar backend/app.jar.bak-$(date +%m%d%H%M) &&
  mv /tmp/app.jar backend/app.jar
'
```

`$(date +%m%d%H%M)` 会展开成当前时间，生成 `app.jar.bak-11151305` 这样的名字，方便回滚时挑版本。

## 7. 规划目录与写配置文件

### 7.1 创建目录

```bash
mkdir -p /var/www/blog/{dist,backend,mysql-init,data/uploads,data/mysql,data/redis}
```

`{a,b,c}` 是 bash 的展开写法，等价于一次写 6 个 `mkdir`。

### 7.2 写 `.env`（密码都在这里）

```bash
cd /var/www/blog
cat > .env <<'EOF'
MYSQL_ROOT_PASSWORD=replace-with-random-hex
REDIS_PASSWORD=replace-with-random-hex
JWT_SECRET=replace-with-long-random-string
MYSQL_DATABASE=blog_db
TURNSTILE_ENABLED=true
TURNSTILE_SECRET=
EOF
chmod 600 .env
```

生成随机串的方法：

```bash
openssl rand -hex 24      # 输出 48 位十六进制，直接复制用
```

每个变量的作用：

| 变量 | 作用 | 注意 |
| --- | --- | --- |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | 只在容器首次初始化时生效；后来改 .env 不会改数据库里的密码 |
| `REDIS_PASSWORD` | Redis 访问密码 | 每次重启都会用这个值，改了要重启 redis 容器 |
| `JWT_SECRET` | 登录令牌签名密钥 | 至少 32 字符；**改了等于让所有人登录失效** |
| `MYSQL_DATABASE` | 数据库名 | 默认 `blog_db` |
| `TURNSTILE_SECRET` | Cloudflare 人机校验密钥 | 留空则跳过校验（本地开发用） |

`chmod 600` 保证只有 root 能读——密码文件权限不对是常见安全事故。

### 7.3 写 `docker-compose.yml`

```yaml
name: blog

services:
  mysql:
    image: mysql:8.0
    container_name: blog-mysql
    restart: always
    mem_limit: 450m
    command: >
      --character-set-server=utf8mb4
      --collation-server=utf8mb4_unicode_ci
      --default-time-zone=+08:00
      --performance-schema=off
      --innodb-buffer-pool-size=128M
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?set MYSQL_ROOT_PASSWORD in .env}
      MYSQL_DATABASE: ${MYSQL_DATABASE:-blog_db}
    volumes:
      - ./data/mysql:/var/lib/mysql
      - ./mysql-init:/docker-entrypoint-initdb.d:ro
    ports:
      - "127.0.0.1:3306:3306"     # 只有服务器自己能用 DataGrip/命令行连
    networks: [blog-net]

  redis:
    image: redis:7-alpine
    container_name: blog-redis
    restart: always
    mem_limit: 100m
    command: ["redis-server", "--requirepass", "${REDIS_PASSWORD:?set REDIS_PASSWORD}", "--appendonly", "yes", "--maxmemory", "64m", "--maxmemory-policy", "allkeys-lru"]
    volumes:
      - ./data/redis:/data
    networks: [blog-net]

  backend:
    build:
      context: ./backend
    container_name: blog-backend
    restart: always
    mem_limit: 450m
    depends_on:
      - mysql
      - redis
    ports:
      - "127.0.0.1:8080:8080"
    environment:
      SPRING_PROFILES_ACTIVE: prod
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/${MYSQL_DATABASE:-blog_db}?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
      SPRING_DATASOURCE_USERNAME: root
      SPRING_DATASOURCE_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      SPRING_DATA_REDIS_HOST: redis
      SPRING_DATA_REDIS_PORT: 6379
      SPRING_DATA_REDIS_PASSWORD: ${REDIS_PASSWORD}
      JWT_SECRET: ${JWT_SECRET:?set JWT_SECRET}
      UPLOAD_DIR: /app/uploads
      JAVA_OPTS: -Xms64m -Xmx280m
    volumes:
      - ./data/uploads:/app/uploads
    networks: [blog-net]

networks:
  blog-net:
```

逐段解释关键点：

- `restart: always` —— 服务器重启、进程崩溃都会自动拉起，这是"网站一直在线"的基础
- `mem_limit` —— 限制单个容器最大内存。1.6G 的小机器必须限，否则 MySQL 会吃掉全部内存导致 OOM
- `--performance-schema=off` —— MySQL 默认开性能监控表，常驻内存 200MB+，小机器关掉能省一半
- `volumes: ./data/mysql:/var/lib/mysql` —— **把容器内的数据目录映射到宿主机**。容器本身是可以随时删除的，数据在宿主机目录里才安全
- `./mysql-init:/docker-entrypoint-initdb.d:ro` —— MySQL 官方镜像的约定：这个目录下的 `.sql` 会在**数据目录为空时**（即首次启动）自动执行。`:ro` 表示只读
- `ports: "127.0.0.1:8080:8080"` —— 冒号前是宿主机绑定地址。写 `127.0.0.1` 表示只有本机能访问，公网连不上；如果写 `0.0.0.0` 或省略 IP，就等于对全世界开放
- `depends_on` —— 先起 mysql/redis 再起 backend（注意：这只保证启动顺序，不保证 MySQL 已经能接受连接，所以后端要有重试逻辑，本项目 Hikari 连接池自带）
- `${VAR:?message}` —— 变量没设置就报错退出，比默认空值安全

### 7.4 写 Dockerfile

`/var/www/blog/backend/Dockerfile`：

```dockerfile
FROM eclipse-temurin:17-jre
WORKDIR /app
ENV TZ=Asia/Shanghai
COPY app.jar /app/app.jar
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar /app/app.jar"]
```

`FROM eclipse-temurin:17-jre` 是官方 Java 17 运行时镜像（只有 JRE，不含编译器，约 180MB）。`COPY app.jar` 把宿主机上的 jar 塞进去。`ENTRYPOINT` 是容器启动时执行的命令。

> 为什么不在服务器上用 `mvn package` 构建？1.6G 的机器跑 Maven 编译会吃掉几百 MB 内存，可能把 MySQL 挤崩。本地构建、上传产物是最稳的做法。

## 8. 初始化数据库

### 8.1 建表（自动）

把建表脚本放到 `mysql-init/`：

```bash
scp deploy/mysql/init/01-schema.sql root@your-server-ip:/var/www/blog/mysql-init/
```

首次 `docker compose up -d` 时，MySQL 容器发现 `data/mysql` 是空的，就会执行这个脚本建出 12 张表。**之后再重启不会重复执行**（因为数据目录已经不为空）。

### 8.2 导入示例内容（可选）

```bash
ssh root@your-server-ip '
  cd /var/www/blog &&
  set -a; . ./.env; set +a &&
  docker exec -i blog-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" blog_db < seed.sql
'
```

- `set -a; . ./.env; set +a` —— 把 .env 里的变量加载成环境变量，`$MYSQL_ROOT_PASSWORD` 才能用
- `docker exec -i` —— 在容器里执行命令，`-i` 保持标准输入（因为要喂 SQL 文件）
- `< seed.sql` —— 把本地文件内容作为命令的输入

### 8.3 创建博主账号（必须）

项目**不内置任何默认账号**。在本地生成密码哈希：

```bash
cd scripts
npm install
node hash-password.mjs '你的密码'
# 输出形如：$2a$10$5eP2CB//NT0QNp/...
```

然后在服务器上插入：

```bash
docker exec -it blog-mysql mysql -uroot -p blog_db
```

进入 MySQL 命令行后：

```sql
INSERT INTO sys_user (username, password, nickname, status)
VALUES ('admin', '$2a$10$5eP2CB//...', '博主', 1);
exit;
```

BCrypt 哈希不可逆，数据库泄露也看不到明文密码。

常见错误对照：

| 日志里的关键字 | 原因 | 解决 |
| --- | --- | --- |

| `Communications link failure` | 连不上 MySQL | 等 MySQL healthy；检查密码是否与 .env 一致 |

## 10. 配置 Nginx 与 HTTPS

### 10.1 放前端文件

```bash
scp /tmp/dist.tgz root@your-server-ip:/tmp/
ssh root@your-server-ip '
  cd /var/www/blog &&
  rm -rf dist.new && mkdir dist.new &&
  tar -xzf /tmp/dist.tgz -C dist.new &&
  rm -rf dist && mv dist.new dist
'
```

先解压到 `dist.new` 再整体替换，是为了避免"文件正被 Nginx 读取时被删掉"的瞬间 404。

### 10.2 站点配置

`/etc/nginx/sites-enabled/blog.conf`：

```nginx
# HTTP 全部跳 HTTPS
server {
    listen 80;
    server_name your-domain.com www.your-domain.com;
    location /.well-known/acme-challenge/ { root /var/www/blog/dist; }
    location / { return 301 https://your-domain.com$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name your-domain.com www.your-domain.com;

    ssl_certificate     /etc/nginx/ssl/your-domain.com.pem;
    ssl_certificate_key /etc/nginx/ssl/your-domain.com.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 35m;     # 允许上传 30MB 音频

    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;
    gzip_comp_level 6;

    # 前端：单页应用，找不到文件就回 index.html
    location / {
        root /var/www/blog/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
        location = /index.html { add_header Cache-Control "no-cache"; }
    }

    # 带哈希的静态资源：长缓存
    location /assets/ {
        root /var/www/blog/dist;
        expires 30d;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # 后端接口
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 上传的封面与音频
    location /uploads/ {
        alias /var/www/blog/data/uploads/;
        expires 7d;
    }
}
```

几个必须理解的点：

- `try_files $uri $uri/ /index.html` —— 前端用的是 Hash 路由其实不太依赖这行，但保留它能兼容直接访问子路径的情况
- `proxy_pass http://127.0.0.1:8080;` —— **结尾不带 `/`**。如果写成 `http://127.0.0.1:8080/`，Nginx 会把 `/api/` 前缀剥掉再转发，后端路由全是 `/api/xxx`，结果就 404
- `client_max_body_size 35m` —— Nginx 默认只允许 1MB 请求体，不调这个上传图片会 413
- `index.html` 单独设 `no-cache` —— 保证发版后用户立刻拿到新版本，而不是用缓存里旧的 index.html 去引用已经删掉的旧 js

### 10.3 申请证书（Let's Encrypt）

```bash
apt install -y certbot
certbot certonly --standalone -d your-domain.com -d www.your-domain.com
```

`--standalone` 会临时占用 80 端口做域名验证，所以执行前先 `systemctl stop nginx`，成功后：

```bash
mkdir -p /etc/nginx/ssl
cp /etc/letsencrypt/live/your-domain.com/fullchain.pem /etc/nginx/ssl/your-domain.com.pem
cp /etc/letsencrypt/live/your-domain.com/privkey.pem  /etc/nginx/ssl/your-domain.com.key
systemctl start nginx
```

自动续期（证书 90 天过期）：

```bash
systemctl enable certbot.timer
```

### 10.4 检查并生效

```bash
nginx -t                    # 语法检查，必须看到 syntax is ok
systemctl reload nginx      # 平滑重载
```

**`nginx -t` 这步千万别跳过**。配置有语法错误时 `reload` 会失败但不影响正在运行的旧配置，而你可能会误以为新配置生效了。

访问 `https://your-domain.com` 应该能看到博客首页。

## 11. 日常运维：更新、备份、回滚

### 11.1 只更新前端（最常见）

```bash
# 本地
npm run build
tar -czf /tmp/dist.tgz -C dist .
scp -C /tmp/dist.tgz root@your-server-ip:/tmp/

# 服务器
cd /var/www/blog
cp -a dist dist.bak-$(date +%m%d%H%M)
rm -rf dist.new && mkdir dist.new
tar -xzf /tmp/dist.tgz -C dist.new
rm -rf dist && mv dist.new dist
```

不需要动容器，刷新页面即可（index.html 不缓存，会立刻拿到新版本）。

### 11.2 只更新后端

```bash
# 本地
cd backend && mvn -DskipTests package
scp -C blog-admin/target/app.jar root@your-server-ip:/tmp/app-new.jar

# 服务器
cd /var/www/blog
cp -a backend/app.jar backend/app.jar.bak-$(date +%m%d%H%M)
mv /tmp/app-new.jar backend/app.jar
docker compose up -d --build backend
```

**必须带 `--build`**：`Dockerfile` 里是 `COPY app.jar`，jar 是在构建镜像时复制进去的。只替换宿主机文件而不重建镜像，容器里跑的还是旧 jar。这是最容易踩的坑。

### 11.3 数据库备份

```bash
mkdir -p /root/backup
docker exec blog-mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines blog_db | gzip > /root/backup/blog-$(date +%F).sql.gz
```

- `--single-transaction` 保证备份期间数据一致（InnoDB 特性，不锁表）
- 上传文件也要备份：`tar czf /root/backup/uploads-$(date +%F).tar.gz -C /var/www/blog/data uploads`

建议加个定时任务：

```bash
crontab -e
# 每天凌晨 3 点备份
0 3 * * * cd /var/www/blog && set -a && . ./.env && set +a && docker exec blog-mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction blog_db | gzip > /root/backup/blog-$(date +\%F).sql.gz
```

### 11.4 恢复

```bash
gunzip -c /root/backup/blog-2026-11-15.sql.gz | \
  docker exec -i blog-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" blog_db
```

### 11.5 回滚

```bash
# 回滚前端
cd /var/www/blog && rm -rf dist && cp -a dist.bak-11151305 dist

# 回滚后端
cp -a backend/app.jar.bak-11151305 backend/app.jar && docker compose up -d --build backend
```

### 11.6 日常检查

```bash
docker compose ps                  # 容器都健康吗
docker stats --no-stream           # 内存占用
free -m                            # 可用内存
df -h                              # 磁盘（日志和备份会慢慢吃掉）
tail -50 /var/log/nginx/error.log  # Nginx 有没有报错
docker logs --tail 100 blog-backend | grep ERROR
```

## 12. 排错手册

| 现象 | 排查顺序 |
| --- | --- |
| **502 Bad Gateway** | 后端没起或挂了 → `docker ps` 看 `blog-backend` → `docker logs blog-backend`；端口是不是 8080；`ss -lntp \| grep 8080` |
| **504 Gateway Timeout** | 请求超过 Nginx 默认 60s，通常是后端卡住或数据库锁 → 看后端日志有没有长查询 |
| **页面白屏** | F12 看 Console 报错；Network 里 js 是否 404（`/assets/` 路径错或 dist 没替换成功）；`try_files` 有没有配 |
| **接口全 404** | `proxy_pass` 结尾多了 `/`，把 `/api` 剥掉了 |
| **上传图片 413** | `client_max_body_size` 没调大 |
| **上传后 403** | `data/uploads` 权限不对 → `chown -R 1000:1000 data/uploads`（容器内非 root 用户） |
| **登录后立刻掉线** | `JWT_SECRET` 改了或 Redis 容器重启丢了会话（`--appendonly yes` 已持久化） |
| **容器反复重启** | `docker logs` 看上一条退出原因；`restart: always` 会无限重试，所以日志里会有多段启动记录 |
| **数据库连不上** | `docker exec blog-mysql mysqladmin ping -uroot -p密码`；检查 .env 与数据库实际密码是否一致 |
| **磁盘满了** | `df -h` → `du -sh /var/lib/docker/*` → `docker system prune`；备份文件也要清理 |
| **中文乱码** | 数据库/表必须是 `utf8mb4`；`spring.sql.init.encoding: UTF-8` |

排错基本顺序永远是：**看日志 → 看进程/端口 → 看资源 → 再看配置**。

## 13. 安全清单

上线前逐条确认：

- [ ] SSH 已改为密钥登录，`PasswordAuthentication no`
- [ ] root 密码强度足够，或直接禁用 root 密码登录
- [ ] 云厂商安全组只放行 22 / 80 / 443，**不要放行 3306、6379、8080**
- [ ] MySQL / Redis 的 ports 都绑定在 `127.0.0.1`（或干脆不映射）
- [ ] `.env` 权限 600，且**没有提交到 git**
- [ ] `JWT_SECRET` 是随机 32 位以上，不是示例值
- [ ] 博主密码是 BCrypt 哈希入库，不是明文
- [ ] 留言/评论开了 Turnstile 或至少有限流
- [ ] 定期 `apt update && apt upgrade`，定期更新镜像（`docker compose pull`）
- [ ] 数据库有定时备份，并**实际演练过一次恢复**
