# 博主身份绑定与发布指南

> 适用版本：第四版（GitOps / GitHub Discussions 评论）
> 相关文件：`src/data/site.ts`、`src/stores/auth.ts`、`src/lib/github.ts`、`.github/workflows/deploy.yml`

这套博客没有服务器、没有数据库，所有「写」的能力都由 GitHub 承担：

```
写文章（后台 / 本地 / GitHub 网页）
   → 提交 commit 到仓库 main 分支
   → GitHub Actions 自动构建（草稿在构建期被物理剔除）
   → 部署到 GitHub Pages
评论：访客用 GitHub 账号登录 → giscus 写入该仓库的 Discussions
```

因此「绑定博主身份」= **让你的 GitHub 账号成为唯一能解锁后台、并且持有仓库写权限的账号**。下面按顺序做一遍即可。

---

## 0. 先准备仓库

1. 把本项目推到 GitHub，默认分支为 `main`（或你喜欢的名字，后面配置里要一致）。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 仓库 **Settings → Actions → General → Workflow permissions** 保持默认的 `Read repository contents` 即可——`.github/workflows/deploy.yml` 里已经声明了 `pages: write` 与 `id-token: write`。
4. 推一次 `main`，确认 Actions 里的「Deploy to GitHub Pages」跑通，能打开 Pages 地址。

> 如果仓库是私有的，Pages 在免费账号下不可用；评论（Discussions）也会受权限影响。建议公开仓库。

---

## 1. 填 `src/data/site.ts`

只需要改这一个文件，里面所有和身份、仓库、评论相关的开关都在这里。

```ts
export const site: SiteConfig = {
  // …前面的站点信息保持不动

  // ① 发布仓库：后台保存时会向这里提交 commit
  repo: {
    owner: 'yulutianchangjun',   // 你的 GitHub 用户名
    name: 'gitHub-blog',         // 仓库名
    branch: 'main',              // CI 监听的分支
    contentDir: 'content',       // 内容目录，一般不用改
  },

  // ② 博主账号：只有这个账号的令牌能解锁后台
  admin: {
    githubLogin: 'yulutianchangjun',
    ownerId: 171635104,   // GitHub 数字 UID，不可篡改，见下文
  },

  // ③ 评论：giscus（GitHub Discussions）
  comments: {
    repo: 'yulutianchangjun/gitHub-blog',
    repoId: '',        // 见第 4 节
    category: 'Comments',
    categoryId: '',    // 见第 4 节
    mapping: 'specific',
    strict: true,
    reactionsEnabled: true,
    inputPosition: 'top',
    lang: 'zh-CN',
    theme: 'transparent_dark',
  },

  // ④ 人机校验：见第 5 节，留空则不启用
  turnstile: {
    siteKey: '',
  },
}
```

改完提交并等 Actions 部署。**`admin.ownerId` 必须填成你自己的 GitHub 数字 UID**（获取方式：打开 `https://api.github.com/users/你的用户名`，取 `id` 字段），填错会导致「该令牌属于 @xxx（UID …），不是本站博主」而无法登录。

> 为什么用数字 UID：GitHub 用户名可以改，UID 终身不变。校验时以 `ownerId` 为准，`githubLogin` 只用于界面展示；若 `ownerId` 留 0，则退化为用户名比对（不推荐）。

## 2. 生成 GitHub 令牌（PAT）

后台保存文章需要「仓库内容写权限」，因此令牌不能只有 `read:user`。

### 方式 A：Classic token（最简单）

1. 打开 <https://github.com/settings/tokens> → **Generate new token (classic)**。
2. Note 随便写，例如 `megumin-blog-admin`；Expiration 建议 30 天或 90 天。
3. 勾选 **`repo`**（完整仓库读写）。如果你只想操作公开仓库，`public_repo` 也够。
4. 生成后复制 `ghp_…`，**只显示一次**。

### 方式 B：Fine-grained token（更小权限，推荐）

1. 打开 <https://github.com/settings/personal-access-tokens> → **Generate new token**。
2. Repository access 选择 **Only select repositories** → 选中这个博客仓库。
3. Permissions：
   - **Contents: Read and write**（提交文章、删除文章、改 `collections.json`）
   - **Metadata: Read**（GitHub 强制要求）
4. 生成后复制 `github_pat_…`。

> 不需要 `workflow` 权限：后台只改 `content/`，不碰 `.github/`。

### 令牌会被存在哪里？

- 只写入 **`sessionStorage`**（键名 `mgm:github-token`），关闭标签页/浏览器即失效。
- 不写 `localStorage`、不写 Cookie、不发往除 `api.github.com` 之外的任何地址。
- 页面刷新后仍然有效（同一标签页），刷新后如果令牌被撤销，第一次保存会报 401。

> 安全边界：这是纯前端应用，任何能在这台电脑上打开 DevTools 的人都能读到 sessionStorage 里的令牌。请只在**自己的设备**上登录，并给令牌设置较短有效期；怀疑泄露时立刻到 GitHub 撤销。

## 3. 绑定博主身份（进入后台）

### 入口

两种方式，都不需要常驻登录按钮：

1. 连续点击左侧栏头像 **5 次**；
2. 或按 **`Ctrl + Shift + L`**（macOS 也是 Ctrl）。

### 验证流程

1. 弹窗里粘贴上一步的令牌，点「验证并进入后台」。
2. 前端调用 `GET https://api.github.com/user`，拿到 `login`。
3. 与 `site.admin.ownerId` 比对数字 `id`：
   - 一致 → 写入 `sessionStorage`，打开管理面板（头部显示 GitHub 头像与 UID）；
   - 不一致 → 提示「该令牌属于 @xxx（UID …），不是本站博主（UID …）」。
4. 后台右上角显示 `@你的用户名 · GitHub 已验证 · 会话级令牌`，点「退出登录」会立即清除会话。

### 关于「离线口令」

第四版已**彻底删除离线口令**（原 `explosion` 后门）。现在只有一条身份路径：GitHub 账号 + 仓库写权限。这样即使有人拿到源码，也无法凭一个写死的字符串进入后台。

### 登录成功但保存失败？

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 401 令牌无效或已过期 | 令牌被撤销 / 复制不全 | 重新生成并粘贴 |
| 403 没有写入权限 | Classic 没勾 `repo`；Fine-grained 没给 Contents 写权限 | 补权限或重发令牌 |
| 404 仓库或文件不存在 | `site.ts` 的 `repo.owner/name` 拼错，或令牌无权访问私有仓库 | 核对仓库地址 |
| 422 提交被拒绝 | 文件路径异常 / 分支不存在 | 核对 `repo.branch` |
| 409 文件已被修改 | 同一文件被别处同时提交 | 刷新页面重试 |

后台「导入导出 → 检查仓库连接」可以直接测试令牌对仓库的读写权限（调用 `GET /repos/{owner}/{repo}` 并看 `permissions.push`）。

## 4. 接通 GitHub Discussions 评论

评论用 **giscus**：它把评论存进仓库的 Discussions，访客必须用 GitHub 账号登录才能发言，因此天然防匿名刷屏。

### 4.1 开启 Discussions 并建分类

1. 仓库 **Settings → Features** 勾选 **Discussions**。
2. 打开仓库顶部的 **Discussions** 标签 → 左侧 **Categories** 旁的铅笔 → **New category**。
3. 名称填 `Comments`（与 `site.comments.category` 一致），格式选 **Announcements**（只有维护者能新建讨论，访客只能在已有讨论下评论，避免乱开帖）。

### 4.2 安装 giscus App

1. 打开 <https://github.com/apps/giscus> → **Install**。
2. 选择 **Only select repositories** → 勾选这个博客仓库。
3. 安装后，giscus 才有权限代表访客写入 Discussions。

### 4.3 拿 `repoId` 与 `categoryId`

1. 打开 <https://giscus.app/zh-CN>。
2. Repository 填 `你的用户名/仓库名`，页面会自动校验并展开配置。
3. Discussion Category 选刚才的 `Comments`。
4. 页面生成的 `<script>` 里有：
   - `data-repo-id="R_kgDO…"`
   - `data-category-id="DIC_kwDO…"`
5. 把这两个值填进 `src/data/site.ts` 的 `comments.repoId` / `comments.categoryId`，提交部署。

### 4.4 为什么 mapping 用 `specific`

本站是 **hash 路由**（`/#/posts/xxx`），`pathname` 永远是 `/`，用 `pathname` 映射会把所有文章塞进同一个讨论。

所以配置为：

```ts
mapping: 'specific',
```

组件会把 `data-term` 设成文章 slug（如 `why-once-a-day`）。giscus 用这个 term 建一条标题相同的讨论，翻页、刷新、分享链接都能稳定对应。

### 4.5 访客看到什么

- 未配置 `repoId`/`categoryId`：评论区显示配置向导（不会伪造本地评论）。
- 已配置：先显示 Turnstile 校验（若启用），通过后加载 giscus；访客点「Sign in with GitHub」授权后即可发言。
- 评论数由 giscus 通过 `postMessage` 回传，显示在评论标题上。

## 5. 配置 Cloudflare Turnstile（人机校验）

### 5.1 创建站点

1. 打开 Cloudflare Dashboard → **Turnstile** → **Add site**。
2. Hostname 填你的 Pages 域名，例如 `yulutianchangjun.github.io`；本地调试再加 `localhost`。
3. Widget Mode 选 **Managed**（大多数访客无感通过）。
4. 创建后得到 **Site Key**（公开）与 **Secret Key**（私密）。

把 **Site Key** 填进：

```ts
turnstile: { siteKey: '0x4AAAAAAA…' },
```

Secret Key **不要**写进前端代码。

### 5.2 当前实现的能力边界

纯静态站点没有服务器，`siteKey` 只能做到：

1. 在加载评论区之前，要求浏览器完成一次 Turnstile 校验；
2. 通过后 30 分钟内不再重复校验（`sessionStorage` 记录）；
3. 真正阻止匿名刷评论的，是 giscus 要求 **GitHub 账号登录** 这一层。

Turnstile token 只有经过**服务端 Siteverify** 才算真正生效。如果你要严格校验，可以加一个 Cloudflare Worker 作为极薄的中间层（不影响静态托管）：

```js
// Cloudflare Worker：POST /turnstile
export default {
  async fetch(request, env) {
    if (request.method !== 'POST') return new Response('Method Not Allowed', { status: 405 })
    const { token } = await request.json()
    const form = new FormData()
    form.append('secret', env.TURNSTILE_SECRET)
    form.append('response', token)
    form.append('remoteip', request.headers.get('CF-Connecting-IP') ?? '')

    const verify = await fetch('https://challenges.cloudflare.com/turnstile/v0/siteverify', {
      method: 'POST',
      body: form,
    })
    const result = await verify.json()
    return Response.json({ ok: result.success === true })
  },
}
```

前端在 `TurnstileGate` 的 `callback` 里把 token POST 给这个 Worker，只有 `ok === true` 才 `emit('verified')`。Worker 的地址写在环境变量里即可，不必进仓库。

### 5.3 常见问题

| 现象 | 原因 |
| --- | --- |
| 组件一直转圈 | 域名没加到 Turnstile 的 Hostname 列表 |
| 提示「校验组件报错」 | Site Key 填错，或站点被删除 |
| 本地开发无法通过 | 在 Turnstile 里补 `localhost`；或开发环境点「本地预览：跳过校验」（仅 dev 出现） |

## 6. 写文章与发布（GitOps）

### 6.1 三种写法

| 方式 | 适合 | 说明 |
| --- | --- | --- |
| 后台可视化编辑 | 日常更新 | 保存 = 调 GitHub API 提交 commit，Actions 部署后生效 |
| 本地 Git | 大批量、改结构 | 编辑 `content/posts/*.md` 后 `git push` |
| GitHub 网页 | 临时改错别字 | 仓库页按 `.` 打开 Web VS Code，或直接编辑文件 |

后台的能力：新建 / 编辑 / 删除、置顶、隐藏、草稿、公开/私密、封面本地上传（压缩成 Base64 写入 frontmatter）、导入 `.md`、综集增删改。

### 6.2 保存后发生了什么

1. `src/stores/content.ts` 调用 `PUT /repos/{owner}/{repo}/contents/{path}`；
2. commit message 形如 `content: 更新《为何我每天只放一发爆裂魔法》`；
3. 同一分支的 push 触发 `.github/workflows/deploy.yml`；
4. Actions 里 `npm run build`，构建期剔除草稿，上传 `dist` 并发布 Pages；
5. 后台当前页面会先用**内存 overlay** 显示改动，标注「已提交」；刷新后看到的就是 CI 部署后的版本。

> 注意：后台保存不会立刻改变线上页面，通常要等 1–3 分钟 Actions 跑完。不要因为「没变化」重复点保存——那会产生多个 commit。

### 6.3 导入 / 导出

- **导出 ZIP**：`posts/*.md` + `collections.json` + `data/messages.json`（留言墙便签）。评论不在包里，它们在 Discussions。
- **导入**：支持 `.md` / `.json` / `.zip`。导入会**逐篇提交**到仓库（同名覆盖），文件多时请耐心等待。
- 后台「丢弃未部署改动」只清内存 overlay，不会撤销已经提交的 commit；要撤销请到 GitHub 上 revert。

## 7. 草稿与私密文章（构建期物理剔除）

### 7.1 写法

```yaml
---
title: 我的私人思考
date: 2026-11-05
draft: true        # 草稿：不发布
# 或
public: false      # 私密：不发布
---
```

两种标记任一命中，都会被 CI 排除。

> 另一种状态 `hidden: true` 只是「不在列表里展示」，正文**仍会**打进 bundle。它适合暂时不想让人看到的随笔，**不适合**放密码或隐私；要真正保密请用 `draft` / `public: false`。

### 7.2 实现方式

`vite.config.ts` 里的 `gitContentPlugin` 在构建时读取 `content/posts/*.md`，只把通过筛选的文件塞进虚拟模块 `virtual:content`：

- **开发（`npm run dev`）**：包含草稿，方便本地预览（文章会显示「草稿」标记）；
- **构建（`npm run build`）**：`draft: true` 或 `public: false` 的文件**不进入任何 chunk**，`dist` 里搜不到标题和正文。

构建日志会打印：

```
[content] 已在构建期剔除 2 篇草稿/私密文章：xxx.md, yyy.md
```

### 7.3 自己验证

```bash
npm run build
grep -r "只有你知道的一句话" dist || echo "没有泄露"
```

注意：**不要**把私密文章放到 `public/` 或直接写进组件，那些会原样复制。

## 8. CI/CD 与数据持久化

`.github/workflows/deploy.yml`：

| 步骤 | 作用 |
| --- | --- |
| `actions/checkout` | 拉取仓库（包含 `content/`） |
| `setup-node` + `npm ci` | 安装依赖 |
| `npm run typecheck` | 类型检查，挡住明显的坏改动 |
| `npm run build` | 构建（草稿在这里被剔除） |
| `upload-pages-artifact` | 打包 `dist` |
| `deploy-pages` | 发布到 Pages |

要点：

- 触发条件只有 `push` 到 `main` 和手动 `workflow_dispatch`；后台提交走的也是这条。
- 构建产物里的文章 = 仓库里的 Markdown，**没有数据库，也没有 localStorage 作为内容源**，所以换设备、清缓存都不会丢文章。
- 想回滚：在 GitHub 找到对应 commit → Revert，Actions 会重新部署。
- Actions 失败先看 `npm run typecheck` / `npm run build` 的日志；最常见是 frontmatter 写坏或图片路径不存在。

## 9. 数据与隐私一览

| 数据 | 存放位置 | 谁能看到 |
| --- | --- | --- |
| 文章 / 综集 | 仓库 `content/` | 公开（草稿构建期剔除） |
| 评论 | 仓库 Discussions | 公开，需 GitHub 登录才能发 |
| 令牌 | 浏览器 `sessionStorage` | 仅当前标签页 |
| 点赞 / 留言墙便签 / 签到 / UV | 浏览器 `localStorage` | 仅本机，不参与公网 |
| 访客统计 | 无第三方脚本 | 只在本机仪表盘展示 |

第四版启动时会做一次 `mgm:data-version` 迁移，清掉旧版本遗留的演示评论、演示便签、假点赞与离线登录痕迹。

## 11. FAQ

**Q：为什么后台保存后页面没变？**
A：保存只是提交 commit，要等 Actions 构建完成。到仓库 Actions 看最新一次运行。

**Q：可以多个人一起写吗？**
A：可以。给协作者仓库写权限，并让他用自己的 PAT 登录；但 `admin.ownerId` 只认一个账号，其他人会被身份校验挡住。若要多作者，把校验改成「检查仓库 `permissions.push`」而不是固定 UID。

**Q：访客一定要有 GitHub 账号吗？**
A：是的，这是防刷的代价。没有 GitHub 账号的访客只能阅读。

**Q：留言墙（三面软木板）为什么不进 Discussions？**
A：giscus 只能以 iframe 形式渲染，无法把讨论数据取出来画成便签、钉在软木板上；而让访客直接调 Discussions API 写入，访客又不是仓库协作者，没有写权限。所以软木板保留为「本机便签」这一装饰性玩法，公开留言统一走 Discussions（页面顶部和编辑器里都有入口）。

**Q：评论能置顶 / 删除吗？**
A：在 GitHub Discussions 里操作，giscus 会同步显示；站点不再提供本地评论管理。

**Q：Turnstile 真的有用吗？**
A：当前是「加载评论前的人机门 + 30 分钟免检」，主要挡脚本；真正的服务端校验需要按 5.2 加一个 Worker。仅靠前端 token 无法阻止有心人伪造请求，但 giscus 的 GitHub 登录仍是更强的门槛。

**Q：令牌泄露了怎么办？**
A：立即到 GitHub Settings → Tokens 撤销；站点侧点「退出登录」清掉 sessionStorage。由于令牌只在前端使用，撤销即失效。
